# ASCII gallery: design

Date: 2026-10-11
Status: built (v1). Section 19 lists where the build differs from this plan.

## 1. Intent

A second, separate take on the photography portfolio: a top-down ASCII world you walk
around in real time. The world is a gallery building drawn in characters; the photos hang
in it as colored ASCII art, and opening one resolves the characters into the real image.

Two renderers are built behind a toggle so they can be compared side by side:

- **A: Canvas 2D cell grid.** Every cell is drawn as a character on a 2D canvas.
- **C: WebGL2 ASCII post-process.** A plain top-down scene is rendered offscreen, then a
  shader turns each cell of it into a character.

### What the user chose

- Photos are ASCII in the world and turn into the real image when opened.
- Smooth real-time movement with a following camera, not turn-based.
- A gallery building: lobby hub with wings.
- Extras for v1: wandering visitors, the Darkroom develop effect, shareable links.
- Explicitly out of v1: minimap and room jump list.
- Both renderers A and C, with a toggle.

### Constraints carried over from the existing project

- Never modify, move or rename the original photos in `Portfolio/`.
- Do not touch `Portfolio/site/`. Another session is actively working on it. This project
  only **reads** `site/public/photos/`.
- No GPS coordinates and no email address anywhere on the site. Place names come from
  `photos.json` (already coarse).
- Test live in headless Chrome with puppeteer-core and `--use-angle=metal`, never in a
  hidden tab (hidden tabs pause `requestAnimationFrame`). The frame loop uses a real
  per-frame `dt`, capped, and never the raw rAF timestamp.

### Success criteria

- You can walk from the lobby into every room and up to every visible photo.
- Every visible photo is recognizable as ASCII art and opens into its real `hi/` image.
- `R` switches between A and C at any moment without losing position or state.
- 60fps on a mid-range laptop in both renderers; smooth on a phone.
- `#/photo/<id>` and `#/room/<id>` links work on a cold load.

## 2. Data source

`../site/public/photos/photos.json` (read only):

- `rooms[]`: `{ id, name, subtitle, kind, photos: [id...] }`. 11 rooms today:
  `medium-format-1..4`, `x-series-1..6` (named by trip or season, e.g. "Kerala 2024"),
  `darkroom`.
- `photos[]`: `{ id, category, camera, lens, focalLength, aperture, shutter, iso,
  filmSimulation, filmStock, date, year, location, width, height, aspect, palette[],
  accent, title, hidden, hero, variantOf, variants[], room, src: { low, hi, xl, ... } }`.

Rules:

- Photos with `hidden: true` are left out of the world. Variants (`variants[]` on the
  original, e.g. `DSCF7438 → DSCF7438-2`) only appear through the viewer's Alt edit toggle.
- Display title is `title || id`.
- The images used are `low/` (512px, ASCII source and C's textures), `hi/` (2560px,
  viewer) and `xl/` (4096px, viewer zoom).

Dev: Vite serves `../site/public/photos` as `/photos`. Build: a small script copies
`photos.json`, `low/`, `hi/` and `xl/` into `dist/photos/`. If `photos.json` is
regenerated by the other project, this site follows on the next load or build.

## 3. Architecture

`Portfolio/ascii/` is its own Vite project. Plain ES modules, no framework, no Three.js,
no runtime dependencies.

```
ascii/
  index.html
  vite.config.js            serves ../site/public/photos at /photos (dev)
  scripts/copy-photos.mjs   build: copy the needed photo files into dist/photos
  src/
    config.js       name, tagline, about (TODO markers; no email)
    main.js         boot, frame loop (capped dt), renderer toggle, wiring
    data.js         fetch photos.json, filter hidden, index by id and room
    layout.js       rooms → tile map: walls, floors, doors, frame slots, labels, props
    world.js        player, collision, camera, focus, visitors, viewer and effect state
    path.js         BFS shortest path on the tile grid
    input.js        keyboard, pointer/tap-to-walk, swipe
    ascii.js        photo pixels → cells (glyph index, fg color, bg color); pure
    viewer.js       HTML overlay viewer
    router.js       hash routes, replaceState, Copy link
    a11y.js         live region caption, hidden list of photo links
    render/
      glyphs.js     font, cell metrics, brightness ramp, glyph atlas (shared by A and C)
      canvas.js     renderer A
      gl.js         renderer C
      shaders.js    GLSL for C
  test/             node --test unit tests
  e2e/              puppeteer-core live tests
  docs/specs/       this document
```

### Renderer interface

Both renderers implement:

```js
init(canvas, glyphs)     // allocate resources
resize(cols, rows, dpr)  // viewport changed
draw(frame)              // one frame
dispose()                // release everything
```

`frame` is a plain object built by `world.js` each tick:

- `camera`: `{ x, y }` in cells, fractional (smooth sub-cell scrolling)
- `map`: the static tile map and per-room baked data (reference, unchanged per frame)
- `entities`: `[{ x, y, glyph, color }]` for @ and visitors, plus their small `·` marks
- `frames`: visible photo frames with `{ id, rect, focused, effect }`
- `effects`: `{ resolve: { id, t }, develop: { id, t }, safelight: 0..1, sway: t }`
- `overlayText`: exact glyph runs that must stay crisp (labels, plaques, HUD, caption)

The world never knows which renderer is active. `R` (or a HUD button) calls `dispose()`
on the current renderer and `init()` on the other. `?r=canvas` or `?r=gl` forces one;
the last choice is kept in `localStorage` (wrapped in try/catch). If WebGL2 is
unavailable or the context is lost, the site switches to A and shows a short note.

## 4. Grid and font

- Monospace cell, height ≈ 2 × width (terminal proportions). All photo sizing accounts for
  this ratio: a frame of `rows` rows for a photo of aspect `a` is `round(rows * a * 2)`
  columns wide.
- Font size is chosen from the viewport so a laptop shows about 150×45 cells and a phone
  about 50×35. Device pixel ratio capped at 2.
- Brightness ramp: ` .:-=+*#%@` (10 levels). Box drawing for frames and walls
  (`┌─┐│└┘`, `#` for structural walls, `+` for doorways), `░` for the darkroom paper.
- `glyphs.js` builds one glyph atlas (white glyphs on transparent) used by C, and the
  same metrics used by A, so both renderers line up cell for cell.

## 5. Floor plan (`layout.js`)

Deterministic: the same `photos.json` always gives the same map.

```
                ┌ MF IV ┐
                ├ MF III┤        Medium Format wing (north)
                ├ MF II ┤
                ├ MF I  ┤
 X Series wing ─┤ LOBBY ├─ Darkroom (east)
 (west)         └───────┘
```

- **Lobby:** the name from `config.js` in large block-letter ASCII, a short about sign,
  and three doorways labelled with their wing.
- **Wings:** a corridor leaving the lobby. Rooms are placed along it in `rooms[]` order,
  alternating sides of the corridor where possible, so the wing has turns and side rooms
  instead of one straight hall. Medium Format rooms go north, X Series rooms west, the
  Darkroom east.
- **Room size** is computed from its photos: frames are laid along the walls with one or
  two cells between them. The room grows until every frame fits. Rooms keep a one-cell
  wall and never overlap (checked).
- **Doors:** `+` cells in shared walls. Each room's name is painted on the floor just
  inside its door, e.g. `═══ Kerala 2024 ═══`, with its subtitle beneath.
- **Frames:** a box-drawn rectangle against a wall, filled with the photo in ASCII.
  Normal prints are 8–10 rows tall; heroes about 1.5×. Very tall panoramas (aspect < 0.5)
  hang as tall banners with a wall segment centred on them. A one-line plaque sits beneath
  each frame: `Title · Camera · Year` (film: `Title · 35mm film · Year`, or the stock).
- **Output:** a 2D array of tiles `{ kind: wall|floor|door|void|prop, glyph, color, room }`,
  the list of frame slots `{ photoId, rect, wallSide, standCell }` (`standCell` is where
  you stand to look at it), label runs, and per-room bounds.

## 6. Movement and camera (`world.js`, `input.js`, `path.js`)

- Player position is continuous, in cells. Holding WASD or arrows moves at about
  12 cells/s; Shift ≈ 2×. Diagonals are normalized.
- Collision is resolved one axis at a time against wall and prop tiles, so you slide along
  walls. The player is about 0.6 × 0.6 cells.
- The camera eases toward the player each frame (critically damped, about 0.15s), so the
  map scrolls smoothly by sub-cell amounts.
- Click or tap the floor: BFS from the player's cell to the target cell over walkable
  tiles, then follow the path. Any key cancels it.
- **Focus:** the nearest frame whose `standCell` is within about 4 cells and in front of
  you is focused. Its border brightens and the caption bar at the bottom shows:
  `Title · Camera · Lens · f/… · 1/…s · ISO … · Place, Year`. Fields that are null
  are left out.
- `E`, `Enter`, `Space` or clicking a frame opens it. Clicking a frame you're far from
  walks you to its `standCell` first, then opens it.

## 7. Photos as ASCII (`ascii.js`)

A pure function, shared by A, the tests, and C's fallback logic:

```js
toCells(imageData, cols, rows, opts) → { glyph: Uint8Array, fg: Uint8Array(rgb), bg: Uint8Array(rgb) }
```

- Each cell averages the pixels it covers (box filter over the source area).
- Luminance (Rec. 709) is contrast-stretched per photo between its 2nd and 98th
  percentiles, so dark film scans don't collapse to dots.
- `glyph = ramp[floor(lum * 9.999)]`, `fg` = cell color with a mild saturation boost,
  `bg` = cell color at about 20% brightness.
- Mono mode (Darkroom): `fg` = red scaled by luminance, `bg` = near-black red.
- **A** calls it once per photo per frame size, from the `low/` image drawn to an
  offscreen canvas, and caches the result. Photos load room by room as the player comes
  within one room of them.
- **C** does the same math in the fragment shader against the photo texture, every frame.

## 8. Renderer A: Canvas 2D (`render/canvas.js`)

- At init and on resize, each room is baked into an offscreen canvas: walls, floor,
  labels, plaques and its ASCII photos (drawn with `fillText` per cell, once).
- Each frame: clear, blit the visible part of the baked rooms with the camera's sub-cell
  offset, then draw dynamic things on top: the focused frame's bright border, @, visitors,
  the sway offset of Darkroom prints, effect stages and the HUD.
- Effects in A step in discrete stages (for example the resolve runs at ½, ¼ and ⅛ cell
  size, computed with `toCells` at finer grids, then a cross-fade to the real image).

## 9. Renderer C: WebGL2 (`render/gl.js`, `render/shaders.js`)

- **Pass 1 (scene):** render into an offscreen framebuffer at screen resolution. Walls
  and floors come from the tile map as colored quads. Photos are textured quads using
  their `low/` image (textures load per room, like A). Darkroom tint and sway are applied
  here.
- **Pass 2 (ASCII):** a full-screen fragment shader. For each output pixel it finds its
  cell, samples the scene buffer across the cell to get average color and luminance,
  picks the glyph from the atlas by luminance, and writes `fg` over `bg` exactly as in
  section 7. A per-pixel "cell size" mask lets regions use a smaller cell size; this is
  how the resolve works (section 10).
- **Pass 3 (exact glyphs):** @, visitors, labels, plaques, frame borders and the HUD are
  drawn as instanced glyph quads from the atlas, so they are never blurred by pass 2.
  The building (walls, floors, props) and the photos go through pass 2; that is the look
  C is being compared on.
- On `webglcontextlost`, switch to A and show a note.

## 10. Opening a photo and the viewer (`viewer.js`)

Transition, about 0.9s (instant with `prefers-reduced-motion`):

1. The camera glides to centre the frame.
2. Start loading `hi/`. While it loads, the plaque shows `[####·····]`.
3. **Resolve:** characters become the real photo.
   - C: the cell size inside the frame shrinks smoothly from one cell to one pixel, then
     the frame samples the `hi/` texture directly.
   - A: stages at ½, ¼ and ⅛ cell size, then cross-fade to an `<img>` laid exactly
     over the frame.
4. The real image expands from the frame's on-screen rect to full screen (FLIP) and
   becomes the HTML viewer.

Viewer (HTML overlay, the same for both renderers):

- Zoom and pan: wheel, pinch, drag, double-click. Switches to `xl/` past 1.5× zoom.
- `I` toggles an EXIF panel. `←` `→` and swipe go to the previous/next photo in walking
  order (room order, then wall order). The world quietly repositions the player in front
  of the new photo so closing lands in the right place.
- An **Alt edit** toggle when the photo has `variants[]`.
- **Copy link** button.
- Esc, the close button or a click outside closes it. The reverse transition plays:
  shrink to the frame, then real image back into characters.
- Adjacent photos' `hi/` images are preloaded. Full-size images are released on close.
- Alt text is the display title.

## 11. Visitors (`world.js`)

- 6 visitors: glyphs `☺` `☻` `&` in muted palette colors, spread across rooms at start.
- Each loops: choose a frame in its current room (or, 30% of the time, the next room),
  BFS to its `standCell`, walk at about 4 cells/s, stand 3–6s with a `·` above it, repeat.
- Cells occupied by the player or another visitor are blocked while planning. If its next
  step is blocked, a visitor waits up to 1s, then re-plans. Visitors step aside if the
  player walks into them.
- Visitors are always drawn as exact glyphs (pass 3 in C).
- They update every frame regardless of focus, using the capped `dt`.

## 12. Darkroom

- **Safelight:** when the player is inside the darkroom, `effects.safelight` eases to 1
  (about 0.5s). All darkroom tiles render in deep red; a very slow pulse (period about 6s,
  ±8% brightness) suggests the light. Off for reduced motion.
- **Clotheslines:** horizontal lines `──╥────╥──` across the room. Prints hang below the
  pins `╥` and sway horizontally by up to ±0.3 cells (period 4–7s, phase per print).
  Landscape scans (e.g. `IMG_4889` 5066×2075) hang wide, portrait scans hang tall.
- **Undeveloped look:** darkroom prints use mono mode (section 7).
- **Props:** an ASCII enlarger and three trays on a bench along one wall. Decorative,
  but they block movement.
- **Develop on open** (about 1.5s, before the normal resolve):
  1. Blank paper: the frame fills with faint `░`.
  2. The image emerges in red mono characters as an exposure value rises from 0 to 1.
     Cells appear once `lum <= exposure`, so shadows show first.
  3. Red cross-fades to the true colors, still as characters.
  4. Then the normal resolve and viewer.
  C runs these as continuous shader parameters; A steps through about 8 stages.

## 13. Links (`router.js`)

- `#/photo/<id>`: on load, place the player at that frame's `standCell`, set the camera
  without easing, and open the viewer with no transition. On Esc you are standing in front
  of it.
- `#/room/<id>`: place the player just inside that room's door.
- While the viewer is open, moving between photos updates the hash with
  `history.replaceState`. Closing the viewer clears it back to `#/room/<id>` of the room
  you're in.
- Unknown or hidden ids: land in the lobby and show `photo not found` for 3s.
- Copy link copies `location.origin + location.pathname + '#/photo/<id>'`. No Open Graph
  pages in v1.

## 14. Failure handling

- `photos.json` fails or is malformed: an ASCII error screen with what failed and a retry
  link.
- A `low/` image fails: that frame fills with a `?` checker pattern; everything else
  continues. A `hi/` failure shows a message in the viewer with a retry button.
- WebGL2 unavailable or context lost: switch to A with a short note.
- `localStorage` throws: ignore and use defaults.

## 15. Accessibility

- Everything works from the keyboard.
- `prefers-reduced-motion`: instant cuts, no camera easing, no sway or pulse, no
  develop animation (stages skipped).
- An `aria-live="polite"` region announces the focused frame's caption.
- A visually hidden `<nav>` lists every photo as a link to `#/photo/<id>`, so screen
  readers have a way in despite the canvas.

## 16. Performance

- Target 60fps on a mid-range laptop in both renderers, smooth on a phone.
- A: baked room canvases; per frame only a blit plus dynamic glyphs. Offscreen canvases
  for rooms far from the player can be released and re-baked on approach.
- C: three passes, one instanced draw for glyphs. Photo textures per room, loaded on
  approach. The scene buffer is reallocated only on resize.
- `?debug` shows FPS, frame time, active renderer, cell grid size and player cell.

## 17. Testing

Unit (`node --test`, no extra dependencies):

- `layout`: same input → identical output; no rooms overlap; every frame's `standCell` is
  reachable from the lobby (BFS); every visible photo has exactly one frame; doors connect
  rooms.
- `ascii`: a uniform gray image maps to the expected glyph; a gradient produces a
  monotonic glyph ramp; mono mode only has red channel; percentile stretch works on dark
  images.
- `router`: parses `#/photo/<id>`, `#/room/<id>`, unknown routes.
- `path`: shortest path around obstacles; no path → null.

Live (`e2e/`, puppeteer-core + system Chrome, headless, `--use-angle=metal`):

- For each renderer: load, walk @ by script through every room, assert the player reaches
  each room and FPS stays above 55 with the 95th-percentile frame time under 20ms.
- Open a photo; assert the viewer shows the `hi/` image. Open a darkroom print; assert the
  develop stages run in order.
- Cold-load `#/photo/<id>` and `#/room/<id>`.
- Toggle `R` mid-walk; assert position and focus are unchanged.
- Screenshots of both renderers at the same three spots, saved to `e2e/shots/` for
  side-by-side comparison.

## 18. Out of scope for v1

Minimap and room jump list, tour mode, sound, guestbook, contact sheet room, gift shop,
Open Graph share pages, time of day, room palette moods.

## 19. As built

- **Lighting (added after v1 review).** `src/light.js`: a lantern that follows you (flickers,
  walls cast shadows), a picture light over every print, a row of lamps in each room, corridor
  lamps, and the darkroom safelight (pulses ±8% over ~6s). Static lights are baked once; the
  lantern is cast each frame into the visible window. Both renderers multiply the result over the
  frame, plus a faint additive haze. Visitors are lit; your `@` and the focus border are not.
- **Movement (added after v1 review).** Acceleration and glide, sliding around door corners,
  string-pulled click paths, and a spring camera with a little look-ahead.
- **Resolve in renderer C** uses the same overlay as renderer A (refining character stages, then a
  cross-fade and FLIP), not a per-pixel cell-size mask in the shader. It looks the same in both
  renderers and keeps `gl.js` simpler.
- **Visitors** use `☺ ☻ &`, wander between prints, stand 3–6s with `·` above them, and step
  aside when you walk into them.
- **Alternate edits** (`variantOf`) are never hung; the viewer's "alt edit" button shows them.
- **Map (added after v1).** `M` or the HUD button opens a floor plan with every room as a button;
  picking one walks you there at a quick pace. On phones the rooms are listed under the plan.
- **Pace.** The brisk pace is the default; holding Shift walks. WebGL (renderer C) is the default
  renderer, with canvas as the fallback.
- **Room sorting** uses each photo's measured colour (`npm run colors`, run before dev and build).
